> «Здравствуйте! Я представляю проект полнофункционального интернет-магазина электроники и техники.
>
> Проект реализован в парадигме **Single Page Application (SPA)** с надежным серверным REST API по принципам **Чистой архитектуры (Clean Architecture)**.
>
> **Стек технологий:**
>
> - **Фронтенд:** Vue 3 с TypeScript и Vite, UI-библиотека компонентов Element Plus, глобальное хранилище Pinia и маршрутизация через Vue Router.

> - **Инфраструктура:** Docker, Docker Compose, многоэтапная сборка (Multi-stage build) и веб-сервер Nginx Alpine в качестве reverse-proxy.
>
> **Ключевые инженерные решения:**
>
> 1. **Чистая архитектура на бэкенде:** чёткое разделение на 4 слоя — HTTP-роутеры $\rightarrow$ Сервисный слой с чистой бизнес-логикой $\rightarrow$ Абстрактные интерфейсы репозиториев $\rightarrow$ Конкретная реализация под SQLite. Оформление заказов атомарно изолировано через паттерн Unit of Work (`ITransactionManager`).
> 2. **Промышленная безопасность авторизации:** stateless Access-токен на базе асимметричной подписи RSA (RS256, 2048 бит) и ротируемый криптостойкий Refresh-токен. Токены хранятся в защищенных `HttpOnly; SameSite=Lax` Cookie, что на 100% исключает кражу токенов через XSS-атаки. На сервере реализован механизм защиты от повторного использования токенов (**Reuse Detection**) и прозрачное авто-обновление сессии.
> 3. **Фронтенд на Vue 3:** компонентный подход (SFC), реактивное состояние на Composition API (`ref`, `computed`), динамические фильтры каталога с синхронизацией в URL, корзина в БД и в Pinia, модальные окна быстрого просмотра и оформления заказов, панель администратора с полным CRUD и ролевым доступом.
> 4. **Надёжность и качество:** весь проект покрыт 21 автоматическим тестом (11 на бэкенде в `node:test` и 10 на фронтенде в `vitest`). Имеется интерактивная OpenAPI/Swagger документация на `/docs`.»

## 2. Vue 3 и Фронтенд на пальцах для новичка (Ликбез без заумных терминов)

Если вы никогда не занимались фронтендом и вас спросят: _«Объясни, как работает твой клиентский код и что тут делает Vue?»_, вот всё, что нужно понимать и говорить.

### 2.1. Что такое SPA и почему страницы не перезагружаются

- **Обычный старый сайт (SSR / Multi-Page):** при каждом клике на ссылку браузер отправляет запрос серверу, экран моргает белым, и сервер присылает целиком новую HTML-страницу.
- **Наш сайт (SPA — Single Page Application):** в браузер единожды загружается один пустой скелет `index.html` и скомпилированный JavaScript-файл приложения. Дальше страницей управляет Vue. При переходе в корзину или каталог **страница не перезагружается вообще**: Vue прямо в памяти браузера стирает ненужные HTML-блоки и мгновенно вставляет новые, подтягивая сырые данные с бэкенда через фоновые сетевые запросы `fetch()`.

---

### 2.2. Анатомия файла `.vue`: Template, Script, Style

Во Vue всё приложение разделено на строительные кирпичики — **компоненты**. Компонент хранится в файле с расширением `.vue` (Single File Component, SFC) и содержит ровно 3 части:

```html
<script setup lang="ts">
  // 1. МОЗГИ (Логика на TypeScript):
  // Здесь объявляются переменные, функции, вызовы API, импорты
</script>

<template>
  <!-- 2. ТЕЛО (HTML-разметка): 
       Здесь пишется то, что отображается на экране пользователю -->
</template>

<style scoped>
  /* 3. ОДЕЖДА (CSS-стили): 
     Слово "scoped" гарантирует, что эти стили применятся ТОЛЬКО 
     к данному компоненту и никогда случайно не сломают другие страницы */
</style>
```

### 2.3. Реактивность: `ref`, `reactive` и `computed`

В стандартном JavaScript, если вы напишете `let count = 0; count = 5;`, текст на экране сам по себе не изменится — нужно вручную находить элемент в DOM и обновлять его текст.
Во Vue используется **реактивность**:

- **`ref(начальное_значение)`** — оборачивает любое примитивное значение (число, строку, булево, массив) в специальный реактивный контейнер.
  ```typescript
  import { ref } from 'vue';
  const count = ref(1); // в коде обращаемся через .value: count.value++
  ```
  В шаблоне `<template>` Vue сам знает про `.value`, поэтому пишется просто `<span>{{ count }}</span>`. Как только `count.value` изменится, Vue мгновенно сам обновит DOM на экране!
- **`reactive({ ... })`** — используется для целых объектов (например, для полей формы с несколькими свойствами: `sku`, `price`, `name`). К его полям обращаются напрямую: `form.name = 'Новый товар'`.
- **`computed(() => выражение)`** — «вычисляемое свойство». Переменная-формула. Например:
  ```typescript
  const totalPrice = computed(() => {
    return cartItems.value.reduce((sum, item) => sum + item.price * item.quantity, 0);
  });
  ```
  `totalPrice` автоматически пересчитается тогда и только тогда, когда изменится `cartItems`. Если ничего не менялось — Vue берет готовый кэш без лишних вычислений.

### 2.4. Директивы шаблонизатора (v-model, v-if, v-for, @click, :prop)

Внутри секции `<template>` используются специальные атрибуты-команды Vue:

1. **`{{ переменная }}` (Интерполяция):** вывод текста внутрь HTML.
2. **`v-model="переменная"` (Двустороннее связывание данных):** магия для полей ввода `<input>` или `<el-input>`. Когда пользователь печатает текст, значение переменной в скрипте меняется мгновенно. Если скрипт поменял переменную — текст в инпуте также мгновенно обновился.
3. **`v-if="условие"` / `v-else`:** условный показ элементов. Если `true` — элемент есть на странице. Если `false` — элемент физически вырезан из DOM-дерева.
4. **`v-for="item in items" :key="item.id"`:** цикл вывода списков или карточек. Атрибут `:key` обязателен — он дает Vue уникальный идентификатор каждого элемента, чтобы при изменении порядка не перерисовывать весь список с нуля.
5. **`@click="имяФункции"` (сокращение от `v-on:click`):** реакция на клик мыши или нажатие кнопки.
6. **`:src="imageUrl"` (сокращение от `v-bind:src`):** привязка динамического значения из JavaScript к HTML-атрибуту (двоеточие показывает: «в кавычках лежит переменная, а не просто текст»).

### 2.5. Как компоненты общаются: `props` и `emit`

Дерево компонентов работает по принципу «сверху-вниз данные, снизу-вверх события»:

- **`Props` (Свойства):** Родитель передает данные в дочерний компонент. Карточка товара не знает, откуда взялся товар, она просто принимает его:
  ```typescript
  // В дочернем ProductCard.vue:
  const props = defineProps<{ product: Product }>();
  ```
  В родителе: `<ProductCard :product="currentProduct" />`. Пропсы менять внутри дочернего компонента нельзя (они Read-Only).
- **`Emit` (События):** Дочерний компонент не должен сам менять глобальное состояние. Вместо этого он сообщает родителю о действии:
  ```typescript
  // В дочернем:
  const emit = defineEmits<{ (e: 'quick-view', product: Product): void }>();
  emit('quick-view', props.product); // "кричит" родителю
  ```
  В родителе: `<ProductCard @quick-view="handleOpenModal" />`.

### 2.6. Vue Router: маршрутизация и Navigation Guards

- Файл: `frontend/src/router/index.ts`.
- Связывает путь в адресной строке браузера с файлом страницы:
  - `/` $\rightarrow$ `HomeView.vue`
  - `/catalog` $\rightarrow$ `CatalogView.vue`
  - `/cart` $\rightarrow$ `CartView.vue`
  - `/admin/products` $\rightarrow$ `AdminProductsView.vue`
- Переход осуществляется без перезагрузки страницы через `<router-link to="/catalog">` или программно: `router.push('/catalog')`.
- **Navigation Guards (`router.beforeEach`):** страж маршрутов. Перед каждым переходом он проверяет:
  - Если страница требует авторизации (`meta.requiresAuth`), а пользователь — гость, перенаправляет на `/login`.
  - Если страница требует прав администратора (`meta.requiresAdmin`), а у пользователя роль `user`, перенаправляет на главную `/`.
  - Если пользователь уже залогинен, не пускает его повторно на страницы входа и регистрации (`meta.guestOnly`).

### 2.7. Pinia: глобальный стейт-менеджер (Контекст приложения)

- Папка: `frontend/src/stores/`.
- **Проблема, которую решает Pinia:** шапка сайта (`AppHeader`) и карточка товара (`ProductCard`) находятся в разных концах дерева компонентов. Если пользователь нажмет «В корзину», как шапка узнает, что нужно обновить счетчик?
- **Решение:** Pinia создает глобальное хранилище в оперативной памяти вкладки.
  - `auth.ts` — хранит данные вошедшего пользователя, его роль (`admin`/`user`) и признак `isAuthenticated`.
  - `cart.ts` — хранит список товаров в корзине, общую стоимость и количество позиций.
    Любой компонент приложения в любом месте может написать:
  ```typescript
  const cartStore = useCartStore();
  cartStore.addToCart(product, 1);
  ```
  И счетчик в шапке сайта, и общая сумма обновятся автоматически во всех компонентах!

### 2.8. Element Plus: UI-библиотека готовых компонентов

Мы не тратили недели на ручную верстку кнопок, диалогов и таблиц на чистом CSS. Проект использует ведущую библиотеку **Element Plus**:

- `<el-button>` — кнопки с поддержкой состояний загрузки (`:loading="isLoading"`), типов (`type="primary"`, `danger`) и иконок.
- `<el-table>` и `<el-table-column>` — мощная таблица в админке с сортировкой, полосатыми строками и кастомными шаблонами ячеек.
- `<el-dialog>` — модальные всплывающие окна с затемнением заднего фона (backdrop).
- `<el-carousel>` — карусель рекламных баннеров на главной странице.
- `<el-form>` и `<el-form-item>` — формы с автоматической подсветкой ошибок валидации по правилам `:rules`.
- `ElMessage.success()` / `ElMessage.error()` — всплывающие toast-уведомления в правом верхнем углу.
- `ElMessageBox.confirm()` — диалог подтверждения удаления («Вы уверены, что хотите удалить товар?»).

### 2.9. Как клиент общается с сервером (`api.ts`, `fetch` и HttpOnly cookies)

- Файл: `frontend/src/api.ts`.
- Внутри написана централизованная асинхронная функция:
  ```typescript
  async function request<T>(path: string, init: RequestInit = {}): Promise<T>;
  ```
  Она вызывает нативный браузерный `fetch('/api' + path, ...)`.
- **Важнейшая настройка:** `credentials: 'include'`. Благодаря ей браузер **автоматически прикрепляет сессионные куки** (`access_token`, `refresh_token`) к каждому запросу на бэкенд и принимает новые куки от сервера.
- Если бэкенд возвращает статус ошибки (4xx или 5xx), функция считывает стандартное JSON-тело `{ error: { code, message, details } }` и выбрасывает типизированную ошибку `ShopApiClientError`, которую мы перехватываем в компонентах и выводим пользователю понятный текст ошибки.

## 3. Обязательный теоретический минимум (Ответы на оценку «3»)

Эти 13 вопросов преподаватель задает для базовой проверки знаний. Отвечайте четко и уверенно по данным формулировкам:

### 1. Как установить зависимости в проекте?

**Ответ:** Зависимости устанавливаются командой `npm install` (или сокращенно `npm i`), выполненной в терминале в каталоге с файлом `package.json`. Менеджер пакетов считывает список нужных библиотек и их версий, загружает их из реестра npm в локальную папку `node_modules` и создает/обновляет файл фиксации точных версий `package-lock.json`.

### 2. Как запускаются клиентская и серверная части?

**Ответ:**

- **Через Docker (Production / демонстрация):** одной командой из корня `docker compose up -d --build`.
- **Локально для разработки (без Docker):**
  - Серверная часть: `cd backend && npm run dev` (или `npm start`).
  - Клиентская часть: `cd frontend && npm run dev` (запускает локальный сервер Vite на порту 5173).
- **Либо из корневого каталога:** `npm run dev` (запуск бэкенда) и `npm run frontend:dev` (запуск фронтенда).

### 3. Где прописываются скрипты для запуска?

**Ответ:** Скрипты прописываются в файле `package.json` внутри специального JSON-объекта `"scripts"`. Запуск любого скрипта выполняется через `npm run <название_скрипта>` (для команд `start` и `test` слово `run` можно опускать: `npm start`, `npm test`).

### 4. Что за файл такой, «package.json»?

**Ответ:** Это главный конфигурационный файл (манифест) любого проекта на Node.js. Он содержит:

- Метаданные проекта: имя (`name`), версию (`version`), тип модулей (`type: "module"` или `"commonjs"`).
- Скрипты автоматизации команд (`scripts`).
- Основные зависимости, необходимые для работы приложения в проде (`dependencies`: Express, Vue, Pinia, Element Plus, SQLite3).
- Зависимости, нужные только на этапе разработки и тестов (`devDependencies`: Vite, Vitest, TypeScript, Nodemon).

### 5. Понятие компонента в React (и параллель с Vue)?

**Ответ:**

- **В React:** Компонент — это независимый, изолированный и переиспользуемый блок пользовательского интерфейса, представляющий собой JavaScript-функцию, которая принимает на вход входные параметры (`props`) и возвращает описание разметки в формате JSX.
- **Во Vue:** Компонент — это аналогичный независимый блок интерфейса, который оформляется в виде Single File Component (`.vue` файла) и инкапсулирует логику (`<script>`), разметку (`<template>`) и стили (`<style>`).

### 6. Что должна возвращать js-функция, чтобы гордо именоваться компонентом?

**Ответ:**

- В React — функция обязана возвращать **JSX-разметку** (React-элемент, например `return <div className="card">...</div>;`) или значение `null` (если компонент временно ничего не должен отображать).
- Во Vue (при функциональном подходе) — функция возвращает виртуальный узел (VNode) через функцию `h('div', ...)`. В стандартном подходе разметка объявляется в секции `<template>`.

### 7. Что такое `<></>` в React (и как это устроено во Vue)?

**Ответ:** В React это **React Fragment** (сокращенный синтаксис для `<React.Fragment></React.Fragment>`). Это служебная псевдо-обертка, позволяющая вернуть из компонента несколько соседних HTML-тегов без необходимости оборачивать их в лишний реальный `<div>`, который мог бы нарушить CSS-сетку или разметку таблицы.  
_Во Vue 3_: компоненты поддерживают множественные корневые элементы в блоке `<template>` нативно (Fragment поддержан из коробки без специальных тегов).

### 8. Что компонент может принять на вход и как оно называется?

**Ответ:** Компонент принимает входные данные, которые называются **`props`** (пропсы, свойства). Они передаются от родительского компонента к дочернему по принципу сверху-вниз. Внутри дочернего компонента пропсы являются неизменяемыми (**Read-Only**), дочерний компонент не имеет права напрямую мутировать полученные пропсы.

### 9. С помощью какой функции в JS делаются запросы в сеть?

**Ответ:** В современном стандарте JavaScript запросы в сеть выполняются с помощью встроенной глобальной асинхронной функции **`fetch(url, options)`**, которая возвращает `Promise`, разрешающийся в объект ответа `Response`. (В устаревшем стандарте использовался объект `XMLHttpRequest`, а в библиотеках — `axios`).

### 10. Какие методы бывают у HTTP-запросов?

**Ответ:**

- **`GET`** — чтение и получение данных с сервера (не должен менять состояние сервера, безопасный и идемпотентный).
- **`POST`** — отправка данных на сервер для создания нового ресурса (регистрация, добавление товара, оформление заказа).
- **`PUT`** — полная замена/перезапись существующего ресурса целиком.
- **`PATCH`** — частичное обновление ресурса (например, изменение только статуса заказа или только количества товара в корзине).
- **`DELETE`** — удаление ресурса.
- **`OPTIONS`** — служебный запрос браузера (preflight) для проверки разрешения CORS перед отправкой основного запроса.
- **`HEAD`** — аналогичен `GET`, но сервер возвращает только заголовки без тела ответа.

### 11. Статусы HTTP-запросов: какие знаете и для чего они такие?

**Ответ:** Все трехзначные статусы разбиты на 5 смысловых категорий по первой цифре:

- **`1xx (Информационные)`:** предварительное подтверждение получения запроса (например, `101 Switching Protocols` при переходе на WebSockets).
- **`2xx (Успех)`:**
  - `200 OK` — запрос успешно обработан, тело ответа содержит запрошенные данные.
  - `201 Created` — ресурс успешно создан на сервере (ответ на POST при регистрации или создании товара).
  - `204 No Content` — запрос успешен, но сервер осознанно возвращает пустое тело (часто при DELETE).
- **`3xx (Перенаправление)`:**
  - `301 Moved Permanently` / `302 Found` — ресурс перемещен по другому URL.
  - `304 Not Modified` — данные не менялись, браузер может взять их из своего кэша.
- **`4xx (Клиентские ошибки — виноват клиент)`:**
  - `400 Bad Request` — ошибка валидации (клиент прислал некорректный JSON или не заполнил обязательное поле).
  - `401 Unauthorized` — клиент не аутентифицирован (нет токена или кука просрочена).
  - `403 Forbidden` — клиент опознан, но у него нет прав на это действие (обычный пользователь полез в админку).
  - `404 Not Found` — запрашиваемый ресурс или роут не существует.
  - `409 Conflict` — конфликт состояния базы (например, попытка зарегистрировать уже занятый email).
- **`5xx (Серверные ошибки — сбой бэкенда)`:**
  - `500 Internal Server Error` — необработанная ошибка в коде бэкенда.
  - `502 Bad Gateway` / `503 Service Unavailable` — сервер-шлюз (Nginx) не может связаться с бэкендом (Node.js упал или перезапускается).

### 12. Что такое схема API и по каким значениям уникальным образом определяется роут/endpoint?

**Ответ:**

- **Схема API:** это формальный контракт спецификации (например, OpenAPI 3.0 / Swagger), описывающий доступные маршруты, поддерживаемые методы, форматы передаваемых параметров (`query`, `path`, `JSON body`), заголовки и детальную структуру ответов для каждого статуса.
- **Уникальность эндпоинта определяется парой: `[HTTP-метод] + [URL-путь]`**.  
  _Пример:_ `GET /api/catalog/products` (получение каталога) и `POST /api/catalog/products` (создание нового товара) — это два совершенно разных роута на сервере, несмотря на одинаковый URL.

### 13. Что такое SQLite и чем она отличается от себе подобных?

**Ответ:**

- **SQLite** — это компактная, встраиваемая (**embedded**), бессерверная (**serverless**) реляционная система управления базами данных (СУБД), полностью поддерживающая транзакции ACID и синтаксис SQL.
- **Главные отличия от клиент-серверных СУБД (PostgreSQL, MySQL, Oracle):**
  1. **Нет сервера как отдельного процесса:** SQLite компилируется и работает непосредственно внутри процесса приложения (Node.js). Нет сетевых накладных расходов на передачу пакетов через сокет.
  2. **Вся база данных — это ровно один файл на диске** (в нашем проекте: `shop.db`), который легко копировать и бэкапить.
  3. **Zero Configuration:** не требует установки СУБД, настройки портов, пользователей и паролей базы.
  4. При активации современного **WAL-режима (Write-Ahead Logging)** читающие запросы не блокируют пишущие транзакции, обеспечивая отличную параллельную производительность.

### Пункт 6. Проектирование и создание БД

- **Файл инициализации:** `backend/db/db.js` и `backend/db/seed.js`.
- **Реализация схемы:** при старте вызывается функция `initDB()`, выполняющая `PRAGMA foreign_keys = ON` и `PRAGMA journal_mode = WAL`.
- **10 реляционных таблиц:**
  1. `users` — пользователи с хешами паролей scrypt, ролями (`user`, `admin`), email с регистронезависимым сравнением `COLLATE NOCASE`.
  2. `auth_sessions` — сессии авторизации с фиксацией User-Agent и IP.
  3. `refresh_tokens` — токены обновления сессии с хешем SHA-256 для защиты при утечке БД.
  4. `user_delivery_addresses` — адреса доставки пользователей.
  5. `categories` — иерархическое дерево категорий с `parent_id`.
  6. `products` — товары со стоимостью `price >= 0`, флагом `is_active`, артикулом `sku` и полем для поиска `search_text`.
  7. `product_categories` — таблица связи многие-ко-многим между товарами и категориями.
  8. `cart_items` — корзина пользователя в базе данных (уникальный индекс `(user_id, product_id)`).
  9. `favourite_user_products` — список избранных товаров пользователей.
  10. `orders` и `order_items` — заказы и позиции заказов с фиксацией цен на момент покупки.
- **Предзаполнение (Seed):** в коде зашиты базовые тестовые пользователи (`demo@example.com`, `admin@example.com`). Дополнительно написан скрипт `npm run seed` (`db/seed.js`), наполняющий базу 21 реалистичным товаром с красивыми фотографиями из Unsplash CDN.

### Пункт 7. Начало работы с REST API

- Спроектирована архитектура API по спецификации OpenAPI 3.0.3 (интерактивный Swagger доступен на `/docs`).
- **Слой репозиториев (Data Access Layer):** выделены контракты `backend/src/repositories/interfaces/` (`IUserRepository`, `IProductRepository`, `ICartRepository`, `IOrderRepository` и др.).

- **Слой бизнес-логики (Service Layer):** `backend/src/services/` — классы `CatalogService`, `CartService`, `AuthService`, `OrderService`. Все вызовы изолированы и тестируемы.

### Пункт 8. Продолжение работы с REST API (express.Router)

- **Главный роутер:** `backend/src/routes/api.js` объединяет все ветки через `express.Router()`:
  - `/api/auth` $\rightarrow$ регистрация, логин, логаут, получение текущего профиля (`/me`).
  - `/api/catalog` $\rightarrow$ список товаров, фильтры, категории, добавление/редактирование/удаление товаров (CRUD).

  - `/api/users` $\rightarrow$ адреса доставки и избранные товары.
- **Middleware:**
  - `authMiddleware.js` — валидация JWT-токена из cookie, прозрачное автообновление по refresh-токену.
  - `roleMiddleware.js` — проверка ролей (`requireRole('admin')`).
  - `errorMiddleware.js` — перехват всех ошибок и формирование стандартизированного ответа `{ error: { code, message, details } }`.

| **Токены и сессии**            | Асимметричный RS256 JWT Access (15 мин) + Opaque Refresh (30 дней) в защищенных `HttpOnly; SameSite=Lax` Cookie. Ротация токенов, защита TokenFamily от повторного использования, автопродление сессии на бэкенде.              |
| **Админка и роли**             | Ролевая модель (`user` / `admin`). На бэкенде middleware `requireRole('admin')`, на фронтенде роуты админки скрыты и защищены навигационным стражем `requiresAdmin`.                                                            |
| **Модальные окна**             | Модалки вынесены в отдельные компоненты: быстрый просмотр товара (`ProductQuickViewModal`), просмотр заказа (`OrderDetailsModal`), ввод адреса (`AddressForm`).                                                                 |
| **База данных**                | SQLite 3 с режимом WAL, внешними ключами `ON DELETE CASCADE`, индексами и транзакциями `BEGIN IMMEDIATE`.                                                                                                                       |
| **Карусельки и UI/UX фишки**   | Промо-карусель баннеров `<el-carousel>`, микроанимации кнопок, плавные переходы, скелетоны и спиннеры загрузки, всплывающие toast-уведомления.                                                                                  |
