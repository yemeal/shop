3. Что происходит при npm start

Инициализация выполняется до того, как порт начинает принимать запросы.

1node index.jsstartServer() выбирает порт из PORT или использует 3000.
2initDB()Открывает SQLite-файл и выполняет SCHEMA_SQL с внешними ключами и индексами.
3Миграция и seedСтарое поле избранного переносится на FK к users; затем создаются демо-пользователь, товар, адрес и заказ.
4createApp({ db })Один объект подключения передаётся в роутер и сервис, поэтому запросы используют ту же БД.
5app.listen(3000)Сервер готов. При SIGINT/SIGTERM вызывается runtime.close().

4. Разбор одного реального запроса: POST /api/orders

Клиент не передаёт цену: сервер сам проверяет товар и фиксирует стоимость.

1РоутorderRoutes.js получает JSON и вызывает orderService.createOrder(request.body).
2ВалидацияПроверяются userId, deliveryAddressId, непустой массив items, положительное количество и отсутствие дублей.
3Проверки БДПользователь существует; адрес принадлежит пользователю; каждый товар активен.
4ТранзакцияBEGIN IMMEDIATE → INSERT в orders → INSERT позиций в order_items → COMMIT. При ошибке — ROLLBACK.
5ОтветgetOrder(orderId) собирает заказ, адрес, позиции и total; роут возвращает 201.

5. Публичный маршрут → внутренние таблицы

Так видно, почему наружу не нужны табличные CRUD-роуты.

GET /api/catalog/productsproducts + фильтр по product_categories; возвращаются только is_active = 1.
GET /api/catalog/products/:idproducts → отдельный запрос категорий через product_categories и categories.
GET /api/catalog/categories/:id/productscategories проверяется отдельно, затем используется тот же сценарий listProducts({ categoryId }).
POST /api/ordersusers + user_delivery_addresses + products → orders + order_items.
GET/POST/DELETE .../favouritesfavourite_user_products связывает пользователя и товар; сам клиент получает объекты products.
